# 카드뉴스 출력

`cards.json`을 템플릿에 적용해 HTML과 PNG를 만드는 절차입니다.
**검증(`npm run validate`) 오류가 0개인 데이터만 출력합니다.** (`render`도 내부에서 먼저 검증합니다)
레이아웃 점검 결과는 스크립트가 제작 기록에 자동으로 남깁니다. (`[대화]` 표시는 대화 모드에서만 하는 일)

## 템플릿 선택 기준

| 템플릿 | 쓰는 경우 |
|---|---|
| `cover` (표지형) | 첫 카드, 마무리 카드. 제목 한 줄이 핵심일 때 |
| `image` (이미지 강조형) | 제품 이미지와 함께 보여줄 대표 특징 1개 |
| `description` (설명형) | 특징 여러 개, 사용 방법 단계처럼 항목이 2~3개일 때 |

템플릿은 구성안 단계에서 정해지므로, 출력 단계에서는 바꾸지 않습니다. 바꿔야 한다고 판단되면 결과를 알릴 때 제안합니다.

## 1. 전체 출력

```
npm run render -- <제품ID>
```

- 결과: `products/<제품ID>/output/html/card-NN.html`, `output/png/card-NN.png`
- 미리보기: `output/html/index.html`에서 전체 카드를 한 화면에서 볼 수 있습니다. (웹에서는 카드 검토 화면이 PNG를 보여줍니다)

## 2. 레이아웃 점검

출력 프로그램이 렌더링 화면 기준으로 자동 점검합니다.

- `OVERFLOW`: 글자가 영역을 넘침 → 해당 카드의 문구를 줄이고 검증 후 그 카드만 재출력
- `IMAGE_ERROR`: 이미지를 불러오지 못함 → 파일명·파일 존재 여부 확인
- 자동 수정은 `CLAUDE.md` 기준 최대 2회입니다.

대화 모드에서는 자동 점검 후 PNG를 직접 열어 아래 항목을 눈으로 확인합니다. 서비스 모드에서는 관리자가 카드 검토 화면에서 확인합니다.
- 제목 줄바꿈이 어색하게 끊기지 않는지 (예: 단어 중간)
- 이미지가 제품을 가리거나 잘리지 않는지
- 요소끼리 겹치지 않는지

문제가 있으면 카드 번호와 함께 알립니다.

오류가 0개면 최종 검토 대기로 넘어갑니다.
`[대화] node scripts/log.js <제품ID> job_finished --ok true` 후 결과를 보여주고 답을 기다립니다.
- 승인: `node scripts/log.js <제품ID> final_approved` 후 `cards.json`의 `stage`를 `"approved"`로 바꿉니다.
- 수정 요청: `cardnews-content` Skill의 '수정 요청'

## 3. 단일 카드 재출력

```
npm run render -- <제품ID> --card N
```

- 지정한 카드의 HTML·PNG만 다시 만들고 다른 카드 파일은 그대로 둡니다.

## 디자인 변경

색상·폰트는 `config/theme.json`, 레이아웃은 `templates/*.html`에서 바꿉니다.
공통 파일이므로 제작 작업 중에는 바꾸지 않습니다. 대화 모드에서 사용자 확인을 받은 뒤 수정하고, 수정 후에는 전체 카드를 다시 출력하고 규칙 버전(`config/skill-version.json`) 변경 여부를 사용자에게 묻습니다.
