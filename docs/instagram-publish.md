# 터미널·웹 게시 기록을 함께 사용해요

## 적용 범위

#110에서 CLI와 작업실이 같은 `ig-publisher.js`를 사용하도록 연결했어요. 공통 기록은 `products/<제품ID>/output/instagram/ig-publish.json`이에요. 게시 버전·진행·결과 링크·사람 확인·예약·불분명 상태를 함께 읽어요. 새 CLI 게시는 예전 `published.json`을 따로 만들지 않아요. 예전 기록은 계속 읽어 같은 카드의 재게시를 막아요.

같은 PC에서 **같은 실제 제품 폴더**를 가리키는 실행끼리 공유해요. 작업실에 `CARDNEWS_STUDIO_SANDBOX=/시험폴더`를 쓰면 CLI에도 `CARDNEWS_PRODUCTS_DIR=/시험폴더/products`를 지정해야 해요. 서로 다른 폴더를 같은 계정으로 쓰는 경우나 여러 서버 사이의 분산 잠금은 이번 범위가 아니에요.

업데이트할 때는 이전 버전에서 진행 중인 게시가 끝났는지 먼저 확인하고, 기존 CLI·작업실을 모두 종료한 뒤 새 버전으로 다시 실행해요. 이전 버전의 프로세스에는 새 파일 잠금이 없으므로 두 버전을 섞어 실행하지 않아요.

## CLI 사용 순서

1. 카드 최종 승인 후 `npm run ig -- caption <제품ID>`로 게시 글을 작성해요.
2. 아래 dry-run으로 카드·캡션·현재 버전·점검 항목을 확인해요. 인스타 API·터널·예약을 실행하지 않으며 게시 기록도 바꾸지 않아요. 캡션 내보내기와 점검 결과 파일은 갱신될 수 있어요.

```bash
npm run ig -- publish <제품ID> --dry-run
```

3. 실제 게시 승인을 받은 뒤 확인한 버전을 넣어요. `--confirm`은 그 버전에 표시된 사람 확인 항목을 모두 검토했다는 뜻이에요. 점검 실패나 중복 게시 차단을 건너뛰는 옵션은 아니에요. 이미 웹에서 같은 버전을 확인했다면 그 확인 기록을 사용할 수 있어요.

```bash
npm run ig -- publish <제품ID> --version <확인한버전> --confirm
```

4. 실패·연결 중단으로 결과가 불분명하면 다시 게시하지 않고 확인해요.

```bash
npm run ig -- verify <제품ID>
```

이 조회는 같은 기록의 상태·링크만 보완해요. 실제 게시를 다시 실행하지 않아요. 이미지 주소를 이미 준비했다면 기존 `--base-url <https주소>`도 사용할 수 있어요. CLI는 예약 타이머를 시작하지 않아요.

## 웹과 함께 쓸 때

- CLI에서 게시하면 웹 상세의 진행·링크·게시 완료와 목록 상태에 반영돼요. 출처는 ‘터미널 게시’로 보여요.
- 웹에서 게시한 같은 버전을 CLI로 다시 게시할 수 없어요. 반대 방향도 같아요.
- 다른 실행에서 게시 중이면 추가 게시·기록 수정은 409로 거절해요. 기다리는 새 게시를 자동으로 쌓거나 실행하지 않아요.
- 예약은 두 경로에서 함께 보여요. 예약된 버전을 CLI로 즉시 게시하려면 먼저 예약을 취소해야 해요. 두 작업실의 예약 확인이 겹쳐도 한 실행만 시작해요.
- 게시 준비 중 원문·카드·캡션 버전이 달라지면 실제 게시 요청 전에 중단해 다시 점검하도록 해요.

## 중단·복구 기준

`products/.ig-publish-locks/`에 실행별 PID·작업 종류만 저장해요. 토큰은 저장하지 않아요. 다른 살아 있는 참가자가 있으면 새 실행은 물러나고, 종료된 프로세스의 참가 파일만 정리해요. 같은 제품 폴더의 별도 프로세스와 symlink 경로도 실제 경로로 맞춰요. 실행 시간만으로 살아 있는 잠금을 지우지 않아요.

새 작업실·CLI가 복구하거나 상세 상태를 읽을 때 다음 기준을 적용해요.

| 저장 상태 | 복구 동작 |
| --- | --- |
| 살아 있는 소유자가 게시 중이에요 | 상태를 덮어쓰거나 다시 실행하지 않아요. |
| 게시 요청 전 실행이 종료됐어요 | 실패로 정리하고 원인을 보여줘요. |
| 게시 요청을 보낸 뒤 종료됐어요 | 확인 필요로 두고 양쪽 모두 재게시를 막아요. |
| 게시물 ID를 받은 뒤 링크 확인 중 종료됐어요 | 게시 완료로 복구하고 링크만 나중에 조회해요. |
| 완료 기록 뒤 제작 로그 저장이 중단됐어요 | 완료 기록을 보존하고 같은 media_id의 이벤트를 중복 없이 보완해요. |
| 기록 파일이 손상됐어요 | 빈 기록으로 바꾸거나 재게시하지 않고 오류를 알려요. |

불분명한 결과 조회에는 요청 당시 캡션 **전체**와 시각을 사용해요. 공통 첫 줄인 ‘AI 활용’만으로 다른 글을 선택하지 않아요. 같은 후보가 여러 개이거나 목록이 늦게 갱신되어 확정할 수 없으면 확인 필요를 유지해요. 컨테이너 실패·만료 등 미게시 근거가 확인돼야 실패로 전환해요.

## 검증과 남은 일

가짜 인스타 API와 임시 제품으로 CLI→웹·웹→CLI 재게시, 별도 프로세스 동시 실행·강제 종료, 예약 경합, dry-run, 옛 기록, 제작 로그 중단, 캡션 오인, 손상 기록을 검사해요. 실제 계정 게시·예약·토큰 갱신은 실행하지 않았어요.

PR #109의 캡션 개선은 사용자 승인으로 main에 병합됐어요. #110 통합의 실제 계정 게시 1회는 사용자 승인 뒤 별도로 확인해요. KT 고정 주소·서버 예약·성과 수집·캡션 편집 화면은 이번에 추가하지 않았어요.
