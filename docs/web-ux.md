# 웹 UI·UX 개편 — 2026-11-03

사용자 요청: 웹 디자인을 세련되고 깔끔하게 정돈하고, 제작 흐름과 필요한 페이지를 개선하며 다크모드를 지원한다.

## 개선 전 문제와 변경

| 문제 | 변경 |
|---|---|
| 제작·결과 보기 목적이 메뉴에서 모호함 | 제작 작업실과 콘텐츠 라이브러리 구분, 로컬 제작 가능 여부에 맞춘 진입 안내 |
| 긴 제품 목록에서 해야 할 일을 찾기 어려움 | 검색·상태 필터·검토할 제품 수·제품별 다음 행동 표시 |
| 입력의 전체 흐름과 저장 후 동작이 불명확함 | 단계 바로가기, 저장과 생성 구분, 이미지 오류 안내, 미저장 이탈 경고 |
| 작은 카드 전체와 긴 문구가 한꺼번에 나타남 | 카드 선택과 큰 미리보기, 문구·원문 근거를 나란히 검토 |
| 실패한 수정 요청이 메모를 지움 | 성공 응답 뒤에만 수정 폼 초기화 |
| 평가·비교가 개발용 안내에 머무름 | 내보낸 실제 평가 데이터 요약과 선택 가능한 프로젝트·카드 비교 |
| 처음 사용하는 사람이 과정을 알기 어려움 | `/guide`에 자료→구성안 승인→검토→내보내기·다운로드 안내 |
| 연한 강조색·일관성 없는 흰 배경·모바일 이동성 | 중립 회색+인디고 토큰, 밝게/어둡게/시스템, 모바일 메뉴·반응형 레이아웃 |

## 데이터와 실행 범위

로컬 제작 API와 작업 실행기, 원문·카드 데이터 규격, 승인 조건, 생성 규칙은 기존 구현을 사용한다. 배포된 정적 사이트에서는 결과 보기만 제공한다. 평가는 내보낸 실행만 집계하며 누락·실패한 전체 실행에 대한 성공률·안전성 성과를 추정하지 않는다. 두 프로젝트가 같은 입력·반복·조건이 아니면 버전 효과로 해석하지 않도록 안내한다.

웹 테마는 `web/src/styles/global.css`의 의미별 변수와 `workspace.css`의 화면 구조에 적용한다. `ThemeControl.tsx`에서 설정 저장·시스템 테마 변경을 처리한다. 카드 아트워크·카드 테마와는 독립적이다. 기존 상세 화면 스타일의 직접 지정된 흰 배경·피드백 색도 테마 변수로 연결했다.

## 확인 범위

- 타입 검사와 Vite 정적 빌드.
- 기존 구성안·근거 7개 + 무드 선택 1개 웹 회귀 검사 통과.
- 추가 `tests/workspace-ui.test.js` 6개: 테마 저장·시스템 연동, 검색·주소 복원·초기화, 실제 프로젝트 경로의 카드 비교·중복 선택, 다크 320px 주요 경로, 작업실 필터·카드 선택·실패 메모 보존, 이미지 오류·필수 선택값·미저장 이탈.
- 데스크톱 1440px와 모바일 320/390px 가로 넘침·콘솔 오류 검사, 밝은 화면·어두운 화면 스크린샷 확인.
- 브라우저 검사는 실제 생성·저장 API 대신 모의 응답 사용. Claude 제작 실행·제품 결과 재출력·평가 실행·배포는 이번 요청에서 수행하지 않음.

## 이어서 할 일

실제 로컬 작업실에서 팀원이 입력→승인→내보내기를 사용하며 버튼명·검토 순서 의견을 수집한다. 기존 승인·내보내기 흐름을 지킨다. 평가의 전체 실행·안전성·핵심 정보 포함률은 평가 집계 규격과 실제 데이터 연결이 준비된 후 보완한다. 공동 UI 파일 변경이므로 양쪽 화면 담당자의 리뷰가 필요하다.
