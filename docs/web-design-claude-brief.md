# Claude Code 웹 UI·UX 개편 작업 지시

작성일: 2026-11-17. 사용자는 UI/UX Pro Max를 적용해 Claude Code가 웹 디자인 개선부터 필요한 후속 기능까지 이어가도록 준비해 달라고 요청했다. **현재 완료한 것은 스킬 설치·작업 지시·인계다. 아래 UI는 아직 구현하지 않았다.**

1. 프로젝트의 `CLAUDE.md`, `AGENTS.md`, `docs/project-context.md`, `docs/handoff.md`, `CONTRIBUTING.md`를 읽고 실제 Git 상태와 대조한다. 제품 제작의 `[웹 모드]`가 아니라 웹 앱을 고치는 **프로젝트 개발 작업**이다.
2. `/Users/lee/git/Cardnews-automation`은 `experiment/gpt-all-cards`이며 제품 삭제·템플릿·GPT 카드 실험 등 많은 미커밋 변경이 있다. 이 폴더에서 reset/clean/stash 자동 복원/브랜치 전환/일괄 커밋하지 않는다. 기존 변경을 UI 변경에 섞지 않는다.

5. 인스타 연결 코드는 별도 폴더 `/Users/lee/.codex/.chatgpt-projects/g-p-6abb113ccf84819189f417d059c9233f/worktrees/cardnews-instagram`, 브랜치 `fix/96-instagram-unified-login`, 커밋 `2591330`에 있다. 읽어 보고 후속 기능 설계에 활용하되 이 폴더의 브랜치를 임의로 바꾸지 않는다.

## 2. 스킬 사용과 디자인 방향

- 먼저 `.claude/skills/ui-ux-pro-max/SKILL.md`를 읽는다. Codex도 같은 파일을 참조하며 별도 규칙 사본을 만들지 않는다.
- `web/package.json`으로 React·TypeScript·Vite·기존 CSS·Pretendard 구성을 확인한다. 이 작업을 위해 Tailwind·Next.js·UI 프레임워크로 전환하지 않는다.
- 제품은 **뷰티 카드뉴스를 제작·검토·게시하는 작업실**이다. 뷰티 쇼핑몰이나 홍보 랜딩 페이지로 만들지 않는다. 카드 이미지가 주인공이고 작업 상태와 다음 행동이 명확해야 한다.
- 사용자는 올드한 세리프·궁서 느낌, 문서처럼 반복되는 레이아웃, 불분명한 생성 진행 상태를 싫어한다. 깔끔하고 젊은 산세리프, 명확한 위계, 정돈된 간격과 적절한 작업 밀도를 사용한다.
- 한국어는 기존 Pretendard를 기본으로 한다. 영문 보조 서체가 필요하면 한국어 혼용·라이선스·로딩 비용을 확인한다. 검색 결과의 영문 서체를 한국어 폰트로 간주하지 않는다.
- 밝은/어두운 모드와 시스템 설정·선택 저장을 유지·개선한다. 중립적인 표면·텍스트와 제한된 포인트색을 토큰화한다. GLOWIF의 베리·블러시 팔레트는 후보이며 최종 브랜드 확정으로 취급하지 않는다.
- 웹 UI 색상과 카드뉴스 제품색은 별개다. 웹 테마 변경으로 생성된 카드의 색·승인 문구·제품 이미지가 바뀌면 안 된다.
- 자동 추천을 검토하여 적용한다. 설치 확인 때 첫 검색은 홍보용 히어로·보라/녹색·Fira Code를 추천해 채택하지 않았다. 좁힌 검색은 Flat Design·Plus Jakarta Sans를, 서체 검색은 Outfit/Work Sans를 반환했다. 산세리프·평면 UI 방향만 참고하며 이 조합·색상을 사용자 확정으로 고정하지 않는다. 작업실에 맞는 정보 구조는 직접 설계한다.

프로젝트 루트에서 필요한 검색만 수행한다. 전체 데이터 파일을 읽거나 장문의 대화를 검색어에 넣지 않는다.

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "creative tool productivity workspace" --design-system -p "Cardnews Studio" -f markdown
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "clean geometric sans" --domain typography -n 2
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "long running progress" --domain ux -n 2
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "form state async" --stack react -n 2
```

검색 결과의 제품 유형·스택·적용 버전을 확인한다. 맞지 않으면 한 번 좁혀 검색하고 부적합한 결과를 최종 디자인 시스템으로 저장하지 않는다. 실제 코드와 시각 검토 후 `design-system/cardnews-studio/MASTER.md`에 채택한 색·서체·간격·컴포넌트·밝게/어둡게 기준과 이유를 기록한다. 기존 MASTER가 있으면 먼저 읽고 보존한다.

## 3. 1차 실행 범위 — 웹 디자인과 제작 UX

이 단계는 아래 범위에서 구현까지 진행한다. 사소한 배치·여백·컴포넌트 선택은 스스로 결정한다.

| 화면 | 개선할 결과 |
| --- | --- |
| `/studio` | 작업 중·대기·검토 필요·완료가 구분되는 목록. 카드 썸네일과 이어서 할 행동을 먼저 보여주기. 새 제작·검색·상태 필터 |
| `/studio/new`, `/:id/edit` | 입력 부담 줄이기. 필수·선택·오류 안내, 자료/이미지 상태, 입력 보존·이탈 방지. 현재 지원하는 입력 필드·API를 기준으로 구성 |
| `/studio/:id` | 입력→구성안→디자인/출력→검토→승인 상태를 한눈에 표시. 현재 단계의 주 행동을 우선 배치. 불필요하게 모든 패널을 길게 펼치지 않기 |
| 구성안·근거 검토 | 승인할 내용·관련 원문을 함께 보기. 승인과 수정 요청을 명확히 구분하고 피드백 입력을 보존 |
| 카드 검토 | 최종 카드 5장 전체 흐름과 한 장 확대 검토. 장별 수정, 글자·근거 확인, 템플릿/AI 결과는 필요할 때 펼치기 |
| 생성·수정 진행 | 서버가 제공하는 실제 단계·경과 시간·대기·실패 원인·재시도 경로 표시. 근거 없는 퍼센트·예상 시간·취소 기능 금지 |
| `/`, `/projects/:id`, `/eval`, `/compare`, `/guide` | 공통 탐색·상태·타이포그래피 통일. 실제 데이터·지표 의미·필터·공유 주소·다운로드·피그마 연결 유지 |

빈 목록·입력 오류·통신 실패·재접속·대기열·작업 실패·승인 대기·완료 상태도 완성한다. 긴 제품명·긴 한국어·URL·좁은 화면에서도 버튼과 핵심 문구를 읽을 수 있게 한다. 새 페이지가 꼭 필요하면 사용자 동선으로 이유를 설명하고 추가하되, 기존 기능을 가짜 버튼으로 대체하지 않는다.

## 4. 인스타 기능 — 현재 동작과 다음 설계

현재 인스타 개발 브랜치에는 게시 전 점검 A1~A4, 계정 확인·캡션·JPEG·공개 이미지 URL·캐러셀 게시 B0~B4가 있다. 실제 첫 게시 `https://www.instagram.com/p/Df024mWj53J/`는 카드 5장·캡션·1→5 순서를 검증했다. 이 코드는 main 미병합이다. 현재 웹은 게시 전 점검까지만 연결됐고 게시는 터미널 명령이다. 웹 게시 버튼 B5·예약·성과 수집 C는 미구현이다.

**1차 UI 완료 뒤 다음 제안을 구체화하고 사용자에게 범위를 확인한다. 앞서 제안된 흐름을 이미 승인된 구현으로 간주하지 않는다.**

제안 흐름은 최종 승인 → 계정/5장/캡션 미리보기 → 게시 전 점검·사람 확인 → 명시적 공개 게시 버튼 → 실제 진행 상태 → 게시 링크다.

다음 기능 설계에는 다음 조건을 포함한다.

- 캡션 편집을 허용할지 확인하고, 허용하면 수정된 내용도 점검과 승인 대상에 포함한다.
- 게시 요청·진행·완료·실패 상태를 서버에 저장하고 새로고침·재시작 후 복원한다.
- 같은 콘텐츠 버전의 중복 클릭·동시 실행을 막고, 통신이 끊긴 경우 실제 게시 여부를 조회한 뒤 재시도를 허용한다. 게시 성공 후 링크 조회 실패를 전체 실패로 처리해 다시 게시하면 안 된다.
- 최종 승인·점검·캡션·이미지 순서를 정확한 버전/해시에 연결한다. 수정되면 재점검한다.
- 새 게시 확인은 사람 최종 승인과 별도다. 이번 UI 작업으로 실제 게시·예약·프로필 변경·토큰 갱신·이미지 재생성을 실행하지 않는다.
- 정적 공개 웹에는 제작/게시 API·인증 값을 포함하지 않는다. 토큰은 기존 로컬 서버 쪽에서만 처리하고 브라우저나 로그로 보내지 않는다.
- 예약·자동 게시·여러 계정·성과 지표 수집은 후속 범위다. 정적 배포만으로 예약이 실행된다고 안내하지 않는다.

## 5. 유지할 제작·콘텐츠 기준

- 사람의 구성안 승인·최종 승인, 원문 근거·문구 검증, 최대 2회 자동 수정과 카드 단위 수정 규칙을 유지한다. UI 개편을 위해 제작 엔진·평가 조건·규칙 버전을 바꾸지 않는다.
- 사용자는 1~5장 전체 GPT 디자인 방향을 정했지만 해당 로컬 실험의 병합·최종 스타일은 별도 상태다. 기존 제품 정체성·승인 문구·색감·세트 일관성을 보존한다. 제품이 다른 제품처럼 보이면 안 된다. 2~4장에 같은 제품 사진을 기계적으로 반복하지 않는 방향도 인계한다.
- 이번 단계는 웹 UI가 중심이다. `templates/`, `config/ai-design.json`, 이미지 생성 프롬프트를 함께 전면 개편하지 않는다. 카드 템플릿 개선이 필요하면 별도 작업으로 제시한다.
- 앞으로 인스타는 팀명 ‘간삼덮’을 제외하고 “이런 화장품이 있으면 어떨까?”라는 가상 뷰티 콘셉트다. GLOWIF·@glowif.beauty·프로필 이미지는 시안이다. 사용자 이름 사용 가능 여부·실제 프로필 적용은 미확인이다.
- 첫 젤크림 게시물은 실제 브랜드 제품 이미지를 쓴 기술 검증이다. 과거 실제 제품·평가 기록을 가상 제품으로 바꾸지 않는다. 가상 제품의 효능도 실제 검증 사실처럼 쓰지 않는다.

## 6. Git 상태와 후속 통합

11.17 원격 확인 기준 main에는 #85 Windows 사용성, #90 브랜드 무드·GPT 배경, V3 대시보드·평가 집계가 반영됐다. #91 제품 합성(main 대상), #93 입력 간소화(#91 브랜치 대상), #95 규칙 v2(main), #98 뷰티 레퍼런스(main), #99 Unified Login(feat/instagram 대상 Draft)는 열려 있다. 작업 시 다시 확인한다.

#99의 기반은 `feat/ax-compliance → feat/instagram`이다. #99 하나가 main에 병합된 것처럼 취급하지 않는다. 1차 UI는 main 기반으로 검증하고, B5 구현 범위가 정해지면 선행 브랜치 통합 계획을 세운다. 실제 V3·평가 진행은 현재 이규동 담당이다. 화면 개선 중 사람 판정 대기·지표 정의·실측 결과를 임의로 완료 처리하거나 가짜 성과를 추가하지 않는다.

## 7. 확인과 전달 기준

- 스킬 체크리스트를 참고해 키보드 이동·포커스·대화상자·접근 가능한 이름·명암비·상태 안내를 확인한다. SVG 아이콘은 기존 `Icon` 체계를 우선 사용한다.
- 375/768/1024/1440px에서 밝게/어둡게 확인한다. 모바일에서는 카드 검토·입력·주요 행동이 가려지지 않아야 한다. 모션 감소 환경을 존중한다.
- `npm test`, `npm run web:build`, `npm run test:web`을 변경 범위에 맞게 수행한다. 카드 템플릿/출력을 수정한 경우에만 출력 검사·calibrate를 추가한다. 실제 제품·로그·인스타 게시 API로 검사를 실행하지 않는다.
- 전후 화면을 저장하고 실제 브라우저에서 입력→승인 대기→수정→카드 검토 흐름을 임시 자료·모의 응답으로 확인한다. 미구현·실패 상태를 성공처럼 표시하지 않는다.
- 작은 변경 단위로 커밋·PR을 준비하고 기존 협업 규칙의 리뷰·병합 흐름을 따른다. `main`에 직접 push하거나 사용자 요청 없이 병합하지 않는다.
- `docs/handoff.md`에 브랜치·변경 파일·완료·미완료·검사·서버 상태·다음 행동을 남긴다. 사용량이 부족해지면 완료한 단위와 다음 행동을 먼저 저장한다.
- 사용자에게 바뀐 화면·동선·검증 결과·남은 결정을 간결하게 전달한다. 특히 웹 개편 완료와 B5 게시 기능 구현 완료를 구분한다.
