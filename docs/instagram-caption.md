# 인스타 게시 글 작성 — #107

## 결정과 적용 범위

사용자는 같은 정보의 반복을 줄이고 새로운 문장으로 쓰는 B 방식을 선택했어요. 카드 편집·평가 조건을 유지하고 게시 글 작성 단계만 추가했어요. 편집 화면은 다른 담당 영역이므로 만들지 않았어요.

## 사용 순서

카드를 최종 승인한 뒤 아래 명령으로 게시 글을 작성해요. 로컬 Claude 로그인이 필요해요. Claude는 작성과 별도 의미 검토에 각각 한 번 사용해요. 동일한 카드·원문·설정의 검토 완료본은 다시 사용해요.

```bash
npm run ig -- caption <제품ID>
# 같은 자료에서 다시 쓰려면 명시적으로 실행해요.
npm run ig -- caption <제품ID> --force
# 캡션 확인과 JPEG 준비도 함께 하려면 아래를 실행해요.
npm run ig -- prepare <제품ID>
```

시험 자료는 `CARDNEWS_PRODUCTS_DIR`로 별도 제품 폴더를 지정해요. 작성·준비 명령은 인스타 API·공개 터널·예약을 실행하지 않아요. 실제 게시·예약은 사용자 승인 뒤에만 해요.

작업실의 기존 게시 패널을 새로 열거나 다시 점검하면 같은 작성본을 보여줘요. 화면 조회나 게시 실행 중에는 모델을 호출하지 않아요. 작성본이 없으면 먼저 caption 명령을 실행하도록 안내하고, 카드·원문·설정·작성 지시가 바뀌었으면 재작성을 요구해요. 기존 CLI publish는 작성본을 재사용하며 게시 순간 새 캡션을 만들지 않아요. CLI와 작업실 게시 잠금 통합은 별도 남은 일이에요.

## 저장·검사 기준

- `output/instagram/caption-draft.json`에 작성 버전·입력 해시·문단별 근거 ID·해시태그·의미 검토 결과의 내용 해시를 기록해요. `caption.txt`는 같은 글의 내보내기 파일이에요. 실제 cards.json·원문·승인 로그는 바꾸지 않아요.
- `resolveCaption`을 준비·작업실이 함께 사용하고, 게시 전 점검도 같은 작성본을 읽어요. 향후 편집 담당의 명시적인 `data.caption.text`가 전달되면 기존 우선순위를 유지해 같은 글을 점검해요. 카드 데이터 스키마 확장이나 편집 저장 API는 이번 범위가 아니에요.
- 첫 줄은 `AI 활용`이고 다음 줄부터 도입을 보여줘요. 본문은 약 300자·2~4문단, 관련 해시태그는 5~8개예요. 샘플·비판매 광고 안내는 본문 뒤에 유지해요. 길이를 넘으면 임의로 자르지 않고 작성 실패로 안내해요.
- 승인 카드의 evidence가 연결한 원문 인용만 근거 목록으로 사용해요. 문단별 근거 ID·수치·주의 표현·중복·길이를 확인하고 별도 Claude 호출로 의미 강화·근거 없는 비교·가상 제품의 사실 단정을 검토해요. 파일·명령·MCP 도구 없이 격리 폴더에서 입력 자료만 전달해요.
- 의미 검토는 자동 보조예요. 의미 전체의 정확성을 프로그램만으로 보장하지 않아요. 게시 전 점검의 ‘게시 글 근거·말투 확인’을 해당 버전에서 사람이 확인해야 작업실 게시·예약이 가능해요. 캡션 변경은 게시 버전 해시·점검·사람 확인을 무효로 해요.
- 카드 생성·평가 규칙 버전은 v2로 유지해요. 게시 캡션은 별도 `caption.writer_version=caption-v1`로 관리해 카드 평가와 구분해요.
- 토큰 값·.env는 작성기에 전달하지 않아요. 모델 오류 원문·인증 출력도 로그에 복사하지 않아요. 실패한 생성·검토 결과를 새 게시 글로 저장하거나 기존 카드 나열 캡션으로 자동 대체하지 않아요.

## 검증과 남은 일

새 검사에는 실제 모델·게시 대신 가짜 Claude 응답·인스타 API와 임시 폴더를 사용해요. 작성·검토 실패, 새 수치·주의 표현, 원문/설정/문장 변경, 캡션 우선순위, 버전 변경 후 재확인을 확인해요. 실제 Claude 작성·별도 근거 검토는 두 사례에서 확인했어요. 두 캡션 모두 원문에 없는 수치·주의 표현이 없어요. 평가용 캡션의 ‘처방’은 원문에 있는 주의 표현으로 표시해 사람이 확인해요. 사람의 최종 의미 확인은 게시 전에 별도로 받아요. 실제 게시·예약·토큰 갱신, 편집 UI, 서버 주소·CLI 게시 기록 통합은 이번에 실행하지 않았어요.

검증 결과는 `npm test` 252개, `npm run test:web` 30개, `npm --prefix web run build` 통과예요. 스키마·카드 템플릿·웹 편집 화면은 변경하지 않았어요.
