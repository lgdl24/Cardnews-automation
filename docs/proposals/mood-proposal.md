## 문제

지금 카드는 제품이 달라도 말투(해요체 고정)·구조(항목 3개)·색(`config/theme.json` 한 벌)이 같아서 브랜드 느낌이 안 난다. 퍼플 톤업 선크림 첫 제작(`products/dalba-toneup-purple`, v1)도 보라색 제품인데 살구·베이지 카드로 나왔다.

## A. 글 무드 (이용석)

### 축을 두 개로 나눔

선케어·보습·진정·탄력은 제품이 **무엇을 하는지**, 프리미엄·비건·더마는 브랜드가 **어떻게 보이고 싶은지**라서 한 목록에 넣으면 조합마다 따로 만들어야 한다. 따로 둔다.

| 축 | 정하는 것 | 정하는 방법 | 개수 |
|---|---|---|---|
| 제품 유형 | 구성안 구조, 꼭 넣을 정보 | 입력 양식 '카테고리'를 고정 목록으로 | 6 (선케어·스킨케어·클렌징·마스크팩·메이크업·바디) |
| 효능 키워드 | 강조점, 주의 표현 검사 강도 | 원문에서 자동 추출 (원문에 있는 것만) | 여러 개 (보습·진정·탄력·미백…) |
| 브랜드 무드 | 말투·어휘 (+ 디자인 프리셋) | 원문에서 판단 + 근거 문장, 구성안 승인 때 사람이 확인 | 3개로 시작 → 5개 |

- 제품 유형별로 구성안에서 먼저 챙길 정보: 선케어 SPF/PA·사용량·덧바르기, 기능성 심사 여부, 클렌징 사용 순서
- 효능 키워드에 '진정'·'탄력'·'주름'처럼 주의 표현과 겹치는 말이 있으면 [주의] 판단을 더 엄격하게

### 무드 문체표 (초안)

같은 원문 "세미 매트 제형으로 … 산뜻 보송한 마무리감"을 무드별로 쓴 예.

| 무드 | 글의 결 | 예시 |
|---|---|---|
| 프리미엄 | 합니다체, 짧고 절제, 감각 형용사 | 산뜻하고 보송한 세미 매트 마무리 |
| 더마·전문 | 사실 위주, 성분·수치·시험 먼저 | 세미 매트 제형 · 번들거림 없는 마무리 |
| 내추럴·순한 | 부드러운 해요체, 편안함 강조 | 가볍게 스며들어 보송하게 감싸 줘요 |
| 클린·비건 (나중) | 담백한 해요체, 인증·성분 투명하게 | 번들거리지 않고 보송하게 마무리돼요 |
| 트렌디·발랄 (나중) | 짧은 구어체, 해시태그 키워드 | 번들거림 NO, #산뜻보송 마무리 |

- 처음엔 프리미엄 / 더마·전문 / 내추럴·순한 3개로 시작
- 무드는 Claude가 원문에서 고르고 근거를 붙인다 (예: 달바 원문 "~선사합니다", "#산뜻보송" → 프리미엄)
- 입력 양식 '브랜드 톤 참고'(선택) 칸: 브랜드 캡션 1~3개나 키워드를 넣으면 우선 참고, 비우면 원문에서

### 지킬 선: 말투만 바꾸고 주장은 못 바꿈

- '더마' 무드라도 원문에 없으면 "피부과 테스트 완료" 못 씀 (특정인·기관 공인 오인)
- '비건' 무드라도 인증 근거가 원문에 있어야 "비건"
- 원문의 '빈틈없이'·'강력한' 같은 과장은 말투를 따라 해도 지금처럼 [주의]로 거름
- `CLAUDE.md` 내용 규칙(원문에 없는 효능·수치 금지, 의미 강화 금지)은 무드보다 위

### 넣는 곳

1. `docs/style-guide.md`: '제품 유형별 구성안 체크리스트', '무드별 문체표' 추가
2. `cardnews-content` Skill 2단계: 제품 유형·효능 키워드·무드를 근거와 함께 고르기
3. `cards.json` `analysis`에 `product_type`·`benefits`·`mood`(+`evidence`) 선택 필드 → 데이터 규격 변경이라 둘 다 승인
4. 규칙 버전 v2로 올림 → A5에서 v1(해요체 고정) vs v2(무드) 비교. 볼 것: 말투가 원문과 닮았는지, [주의]·근거 오류가 안 늘었는지. `eval-exaggerated-cream`으로 '무드를 따라 하다 과장까지 따라 하지 않는지' 확인

## B. 제품 색 무드 (이규동, #38)

제품 사진(`images/main.png`)에서 가장 많이 쓰인 색을 뽑아 카드 색 7개를 만들고, 글자가 올라가는 자리는 대비를 자동 검사한다. 템플릿 HTML은 그대로, `--color-*` 값만 바뀐다.

### 시제품 결과 (저장소 코드는 안 고침)

- 대표 색: 투명·흰색·회색 픽셀을 빼고 색상 10° 구간별 채도 가중 집계 → 가장 큰 구간 평균. 색 있는 픽셀이 2% 미만이면 기본 테마
- 색 7개: 같은 색상으로 bg·text·muted·primary·accent, surface·on-primary는 흰색
- 대비 검사 7곳 (WCAG AA 4.5): text/bg, text/accent(표지), text/surface(설명 항목), muted/bg, muted/accent, on-primary/primary(뱃지), primary/accent(설명 번호). 미달이면 주색·보조 글자를 어둡게
- 출력에 이미 쓰는 Playwright 페이지(canvas)에서 계산 → 새 의존성 없음
- 달바 톤업 선크림 4색 누끼컷 + 실제 템플릿 3종으로 출력 → 4색 모두 7곳 4.5 이상

| 제품 | 대표 색 | primary | accent | 자동 조정 |
|---|---|---|---|---|
| 퍼플 | #8C7E97 | #7E50A5 | #E6DFEC | 주색 50→48% |
| 핑크 | #B3948A | #915746 | #ECE2DF | 주색 50→42% |
| 블루 | #75AEC4 | #376C81 | #DEE9ED | 주색 50→36%, 보조 글자 40→38% |
| 그린 | #86A688 | #38753C | #DFECE0 | 주색 50→34%, 보조 글자 40→38% |

밝은 색(블루·그린)은 대비를 맞추느라 주색이 사진보다 한 톤 어두워진다. 더 밝게 가려면 주색은 장식(선·뱃지)에만 쓰고 글자는 짙은 색으로 두는 방법도 있다.

### 넣는 곳

- 제작 조건에 선택 칸 (예: `색: 기본 | 제품 색`), 없으면 지금처럼 기본 테마
- `render`에서 색 계산 → 대비 검사 → `render-report.json`에 대표 색·색 7개·대비·자동 조정 기록, 못 맞추면 경고
- 기본 테마도 같은 대비 검사를 통과하는지 테스트
- 웹 데이터에 쓴 색을 남길지 (V2에서 보여줄지)

### 제품컷 속 캐릭터를 배경으로 쓰기 → 보류

가상 제품컷(튜브에 캐릭터 인쇄)으로 해봤다.

- 색 차이로 배경 지우기는 안 됨. 흰 캐릭터가 크림색 튜브 위에 있으면 기준을 느슨하게 하면 튜브가 남고, 빡빡하게 하면 캐릭터 일부가 지워짐
- 제대로 하려면 배경 제거 AI 모델(rembg 등)이 필요 → 새 의존성·모델 파일, 결과 확인도 사람이
- 누끼컷 안 캐릭터는 작아서(예: 100×180px) 1080 카드 배경으로 키우면 흐려짐
- 캐릭터는 별도 저작권·라이선스라 제품 사진 사용 가능과 따로 확인해야 함
- 대안: 입력 양식 이미지 칸에 '장식' 용도로 배경 없는 캐릭터 PNG를 따로 받고(출처·사용 가능 여부 필수, '가능'일 때만), 표지·마무리 카드 장식 원 자리에 글자 영역을 피해 배치
