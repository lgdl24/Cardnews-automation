# 작업실 ↔ 피그마 플러그인 (웹에서 바로 피그마로, 고친 카드는 다시 웹으로)

- 상태: **구현·시험** (2026-11-02, 이규동 요청 · Claude). 브랜치 `feat/figma-export`. 제작 규칙·템플릿·출력(`npm run render`)은 안 바꿈
- 앞 단계: [출력 카드 → 피그마](figma-export.md) (레이어 나누기). 이번에 그 결과를 **웹 버튼 + 피그마 플러그인**으로 이음

## 흐름

```
작업실 제품 화면 '피그마에서 편집' ─▶ figma-export (글자·도형·이미지 레이어, Claude 안 씀)
        │  (피그마 파일도 함께 열림 · 연결 코드 표시)
        ▼
피그마 데스크톱 › 플러그인 '카드뉴스 작업실 연결' ─ 가져오기 ─▶ 제품 페이지에 card-01~05 프레임 (편집 가능)
        │  사람이 직접 고침
        ▼
플러그인 '고친 카드를 웹으로 보내기' ─▶ 작업실: 1080px PNG 저장 + 글자 레이어를 승인 문구와 비교
                                        → 화면에 '피그마에서 고친 카드', 문구가 바뀌었으면 [주의], ZIP 받기
```

- 피그마 일반 API(REST)는 디자인을 만들 수 없어서, 만들기·내보내기는 피그마 안에서 도는 **플러그인**이 함. Claude 사용량·피그마 호출 제한과 무관
- 플러그인은 피그마 데스크톱에서 돌아서 **Mac에 설치된 Pretendard를 그대로 씀**(Claude의 use_figma 경로는 Gothic A1로 바뀜)
- 프레임 만드는 코드는 하나(`scripts/lib/figma-builder.js`): Claude 경로(`figma-export`의 build-*.js)와 플러그인(`figma-plugin/code.js`)이 같이 씀

## 처음 한 번: 플러그인 등록 (피그마 데스크톱)

1. 피그마 데스크톱 앱에서 아무 디자인 파일을 엶
2. 메뉴 **Plugins › Development › Import plugin from manifest…** → 저장소의 `figma-plugin/manifest.json` 선택
3. 그다음부터는 **Plugins › Development › 카드뉴스 작업실 연결** (최근 플러그인에도 나옴)

플러그인은 개발용이라 내 컴퓨터에만 등록됨(배포 안 함). 접속은 `http://localhost:5173`·`127.0.0.1:5173`(작업실)만 허용(`manifest.json` `devAllowedDomains`).

## 쓰는 법

> **카드 이미지가 없으면** (새 폴더·다른 컴퓨터: `output/`은 git에 안 올라감) 제품 화면에 '카드 이미지 다시 만들기'가 나와요. 승인된 문구 그대로 이미지만 다시 출력(약 6초, Claude 안 씀, 제작 기록에 안 남김). 이게 없으면 '내보내기'는 `PNG_MISSING`으로 실패하고 '피그마에서 편집'은 안 보여요. 실패하면 이제 이유가 화면에 그대로 나옴(전에는 'HTTP 422'만)

1. `npm run studio` → 제품 화면(카드 출력 뒤)에서 **피그마에서 편집** → 레이어 준비(약 20초) + `config/figma.json`의 피그마 파일이 열림
2. 플러그인 실행 → 화면에 나온 **연결 코드**(6자리) 입력 → 연결 → 제품 고르고 **피그마로 가져오기**. 코드는 플러그인이 기억함(작업실을 다시 켜면 코드가 바뀜)
3. 피그마에서 고침
4. 플러그인 **고친 카드를 웹으로 보내기** → 작업실 화면 '피그마에서 고친 카드'에 나옴. **고친 카드 ZIP 받기**로 내려받음

## 보안

- 작업실 API는 원래 이 컴퓨터(localhost)·같은 출처만 받음. 플러그인은 다른 출처(피그마)라 `/api/studio/figma/*`만 따로 열고 **연결 코드**(작업실을 켤 때마다 새로 만드는 6자리)로 막음. 나머지 API는 그대로
- 개발 서버 자체 CORS는 끔(`web/vite.config.ts` `cors: false`, 웹 화면은 같은 출처라 필요 없음) → 다른 사이트가 개발 서버 파일을 읽지 못하고, 피그마용 경로만 작업실이 직접 허용
- 받은 이미지는 PNG 시그니처·크기(10MB) 확인, 카드 이름은 `card-NN`만, 글자는 200개·2,000자까지만

## 피그마에서 고친 결과의 위치

- `products/<제품ID>/output/figma-edited/card-NN.png` + `edited.json`(받은 시각, 카드별 바뀐 글자). `output/`이라 git에 안 올라감
- **최종본(`output/png`)·`cards.json`·결과 보기 웹은 안 바뀜.** 피그마 수정본은 '사람이 마지막에 다듬은 별도 결과'로 둠
- 문구 비교: 레이어 이름 + 같은 이름 중 몇 번째(설명형 항목처럼 이름이 같은 레이어가 여럿)로 짝지어, 공백·줄바꿈 차이는 같은 문구로 봄. 바뀐 문구는 원문 근거 검증을 거치지 않았으므로 화면에 [주의]. 문구 수정은 작업실 '수정 요청'이 원칙

## 시험 (2026-11-02, 클라우드)

| 확인 | 결과 |
|---|---|
| 작업실 실제 서버(`npm run studio`)에서 준비 → 플러그인 요청(목록·레이어·이미지 14개) | 성공. 미리 요청(OPTIONS)·사설망 허용 헤더 확인, 일반 API에는 CORS 헤더 없음 |
| 플러그인과 같은 프레임 만드는 코드를 실제 피그마에서 실행 (퍼플 5장) | 프레임 5개, 빠진 이미지 0. 이 환경 글꼴은 Gothic A1(피그마 데스크톱에서는 Pretendard) |
| 플러그인 '보내기' 단계(프레임 PNG 내보내기·글자 모으기)를 실제 피그마에서 실행 | 5장 모두 1080px PNG, 글자 레이어 순서대로 |
| 고친 카드 보내기 → 작업실 | 4번 카드 둘째 항목만 바꾼 것을 정확히 잡음(같은 이름 레이어 3개 중) |
| 작업실 화면 (1280px·390px) | 패널·[주의]·카드·ZIP 버튼 표시, 가로 넘침·콘솔 오류 없음 |
| 자동 테스트 | `tests/figma-plugin.test.js` (API 흐름·연결 코드·잘못된 본문, code.js 최신 여부, 가짜 피그마로 프레임 함수) |

**아직 못 한 것: 피그마 데스크톱에서 플러그인 자체(화면·네트워크) 실행.** 이 클라우드에서는 피그마 데스크톱을 띄울 수 없어 이규동 Mac에서 한 번 확인 필요. 막히면 볼 곳: 플러그인 화면의 오류 문구, 작업실 터미널 로그.

## 고칠 때

- 플러그인 본체 `figma-plugin/main.src.js`, 화면 `figma-plugin/ui.html`, 프레임 함수 `scripts/lib/figma-builder.js`
- 본체·함수를 고치면 `npm run figma-plugin`으로 `figma-plugin/code.js`를 다시 만들어 함께 커밋(테스트가 확인)
