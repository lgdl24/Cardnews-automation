# Glowif 리뷰 기반 제작

Glowif는 스킨케어 리뷰에서 여러 상품에 걸쳐 반복된 불편을 찾아 가상 제품을 제안해요. 첫 버전은 [AI-Hub 71603](https://www.aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&currMenu=120&dataSetSn=71603&topMenu=)에서 받은 쇼핑몰 스킨케어 라벨링 ZIP을 사용해요. 테스트 자료에는 2016~2022년에 작성된 리뷰가 들어 있어요.

## 실행 방법

프로젝트 의존성, Playwright Chromium, Python 3.11 이상이 필요해요. 제품 누끼와 카드 디자인은 기존 Codex 로그인으로, 카드 문구 작업은 기존 Claude Code 로그인으로 실행해요.

```sh
# 집계와 후보 확인
npm run glowif -- /보관경로/AI-Hub-Sample.zip --scan

# 근거가 가장 넓게 분포한 후보의 누끼와 검토 대기 구성안 생성
npm run glowif -- /보관경로/AI-Hub-Sample.zip

# 주제를 지정하거나 이미 생성·확인한 투명 제품 PNG를 쓸 때
npm run glowif -- /보관경로/AI-Hub-Sample.zip --topic sticky-finish --image /보관경로/main.png
```

스킨케어 부정 라벨과 관련 표현이 같이 잡힌 리뷰를 세요. 동일 리뷰는 ID와 상품명·정규화한 본문 조합으로 중복 제거해요. 최소 리뷰 5건 및 서로 다른 상품명 3개를 첫 버전의 기준으로 두고, 상품명 수가 같으면 리뷰 수를 비교해요. 숫자는 검토 후보의 키워드 집계라 문맥에 따른 오탐·누락과 상품명 표기 차이가 있을 수 있어요. 후보 제품 설정과 집계 규칙은 `config/glowif.json`에 있어요.

제품 하나를 `products/glowif-…/`에 저장해요. 같은 주제로 재실행하면 기존 초안 링크를 반환해요. 시험 폴더를 쓰려면 CLI에 `CARDNEWS_PRODUCTS_DIR=<시험 폴더>/products`, 개발 서버에 `CARDNEWS_STUDIO_SANDBOX=<시험 폴더>`를 주세요. KT에서는 작업실 서비스와 같은 제품 경로를 지정해요.

## 작업실에서 검토

1. 사이드바 **Glowif**에서 후보 제품과 관련 리뷰 집계를 확인해요. 제품을 열면 기존 검토 화면으로 이동해요.
2. 구성안에서 1장 상황과 제품명·답을 담은 부제, 2장 문제에 답하는 핵심 특징, 3장 상세 특징, 4장 사용법, 5장 문제와 답을 묶는 마무리를 확인하고 승인해요.
3. 기존 문구 검증과 미리보기를 거쳐 GPT가 1~5장 전체를 디자인해요. 같은 색·글꼴 방향을 쓰며 제품 컷, 제형 그래픽, 단계 안내 등 장별 배치를 바꿔요. 제품이 들어가는 장은 색과 위치를 비교한 뒤 같은 원본 누끼를 다시 얹어요. 빠진 카드만 다시 생성할 수 있어요.
4. 현재 문구로 만든 GPT 카드 5장이 모두 있어야 최종 승인할 수 있어요. GPT가 그린 글자, 제품 표시와 가상 제품 배지를 실제 이미지에서 확인해 주세요. 인스타 게시·예약에는 기존 승인과 게시 전 점검을 사용해요.

리뷰 원문·상품명은 ZIP 안에서 읽고, 제품 폴더에는 주제, 집계, 작성 기간만 기록해요. GPT에는 가상 제품 설정과 카드 문구를 전달해요. 리뷰에서 느낀 불편을 가상 제품의 검증된 효능처럼 표현하지 않아요.

## 정기 수집

최신 리뷰를 받을 수 있는 권한 있는 출처가 확보되면 서버에서 하루 한 번 마지막으로 가져온 시점 이후의 자료를 확인해요. 이미 다룬 주제와 근거가 부족한 날은 생성을 건너뛰도록 이어갈 예정이에요. AI-Hub 파일은 초기 검증 자료로 사용하고, 이번 단계의 시작은 위 로컬 명령으로 해요.
